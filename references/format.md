# 工作目录的写法

一部作品一个工作目录，比如 `~/线团/权力的游戏/`。`build_clew.py` 读这些文本文件，生成 `.clew`。
所有文件 UTF-8，`#` 开头的行是注释，空行忽略。

## work.json

```json
{
  "name": "权力的游戏",
  "summary": "HBO 电视剧《权力的游戏》第一至八季的人物关系：七大王国的家族、守夜人与长城以北、厄索斯的坦格利安。关系按全剧完结时的认知整理，含剧透。",
  "tags": ["剧集"]
}
```

- `name`：线团名称，就用作品名；同一作品有多个版本时加上版本（「红楼梦（87 版电视剧）」）。
- `summary`：几句话说清是哪部作品、哪个版本、覆盖到哪里（第几季、全书），最后一句注明「关系按完结时的认知整理，含剧透」。不写版权声明，不写「由 AI 生成」。
- `tags`：一两个，常用「书」「剧集」「电影」「动画」「漫画」「游戏」「历史」。
- `id`、`revision` 不要手写，`build_clew.py` 第一次生成时写进去，之后每次加 1。**不要删这两个字段**：
  线团靠它们认出「同一份关系图的新版本」。

## people.txt

```
## 史塔克家族
艾德·史塔克 | 奈德, 临冬城公爵 | 临冬城公爵、北境守护，劳勃国王的挚友，后任国王之手。
琼恩·雪诺 | 伊耿·坦格利安 | 名义上是艾德的私生子，实为莱安娜与雷加之子。加入守夜人，后任总司令、北境之王。
```

每行：`名字 | 别名 | 简介`。

- **名字**：作品里最通行的叫法，用户语言的通行译名（中文用户用中文译名）。同名的两个人要加区分（「伊蒙·坦格利安（学士）」）。
- **别名**：逗号分隔，可空。真名、昵称、称号、常见的另一种译名都可以放，方便用户搜索。
- **简介**：一两句、几十个字，说清身份和在故事里的位置。只写有依据的事实。
- `##` 分组只是给人看的注释，顺序就是导出顺序：主角和核心家族放前面。

## relations.txt

```
艾德·史塔克 > 罗柏·史塔克 | 亲属 | 父亲 / 长子
琼恩·雪诺 > 艾德·史塔克 | 亲属 | 外甥 · 名义上的私生子 / 舅舅 · 名义上的父亲
琼恩·雪诺 = 山姆威尔·塔利 | 社交 | 挚友
瑟曦·兰尼斯特 > 劳勃·拜拉席恩 | 情感 | 王后 / 丈夫
```

- **有方向**：`A > B | 大类 | A 是 B 的… / B 是 A 的…`。读法是「艾德是罗柏的**父亲**，罗柏是艾德的**长子**」。
  `/` 后面可以省略，但能写就写，两个方向都有称呼时关系图更好读。
- **对称**：`A = B | 大类 | 称呼`，只写一个称呼（朋友、同门、兄弟、盟友）。
- **每对人物只有一根线**。关系有多层（既是亲戚又是恋人，先是盟友后成仇敌），用「 · 」连在同一行，大类选最主要、最能说明两人关系的那一层。
- 写**作品完结时的最终认知**：身世揭晓、背叛、死亡都按结局写。称呼本身不写「已故」。
- 称呼要短，2–6 个字为宜；不清楚具体称谓时用功能性的说法（「主人」「部下」「对手」）。

### 大类

| 大类 | 用在 |
|------|------|
| 亲属 | 血缘、婚姻带来的亲戚（夫妻也可以算情感，看哪层更主要） |
| 情感 | 恋人、夫妻、暗恋、旧情 |
| 敌对 | 仇人、对手、杀害 |
| 从属 | 主仆、君臣、师徒、上下级、效忠 |
| 社交 | 朋友、同学、同事、盟友、邻居 |
| 其他 | 以上都不贴切时 |

英文作品可以写 `kin / romance / hostile / subordinate / social / other`，繁体「親屬 / 敵對 / 從屬」也认。
